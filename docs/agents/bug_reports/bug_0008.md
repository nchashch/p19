## Summary

A client launched with `--no-common-assets` (the documented GPU-less fleet mode) **panics**
the moment the pause modal opens: `modal_menu::spawn_modal_menu` builds control tips that
resolve keyboard/mouse icon glyphs, and `input_icons.rs`'s atlas lookup hits an
`expect("mouse_move.png is always present in the keyboard/mouse pack")` — false in this
mode, because `CommonAssets`' icon-atlas fields are `Option<Handle<Image>>` and the
placeholder collection leaves them `None`. The client process dies; a windowed or
manifest-driven `--mcp` client is unaffected.

## Steps to reproduce

```sh
./target/release/p19-server &            # or any running server
./target/debug/p19-client --mcp --no-common-assets &
curl -s http://127.0.0.1:15702 -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"game/trigger","params":{"event":"connect"}}'
# poll game/state → Lobby; then (server InGame) play:
curl -s http://127.0.0.1:15702 -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"game/trigger","params":{"event":"play"}}'
# open the pause modal:
curl -s http://127.0.0.1:15702 -H 'Content-Type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"game/keyboard","params":{"key":"Escape","pressed":true}}'
```

## Expected vs actual

- **Expected:** the modal opens (control tips degrade, as every other `CommonAssets`
  consumer does in this mode).
- **Actual:** the client panics ~1 s after Escape.

## Evidence

```
thread 'Compute Task Pool (4)' panicked at crates/client/src/ui/input_icons.rs:463:14:
mouse_move.png is always present in the keyboard/mouse pack
Encountered a panic in system `p19_client::ui::modal_menu::spawn_modal_menu`!
```

## Root cause

`input_icons.rs` has one `Option`-degrading path for a *missing atlas file* but at least one
expect-style path (line 463) that assumes the keyboard/mouse pack atlas **handle** itself is
present. `modal_menu`'s control tips are the first consumer that renders in this mode. The
optional-furniture contract (playtest 0010) says every consumer degrades when a key is
absent; this path was missed.

## Fix

Fixed by the client UI migration to bevy_markup (ADR 0015), uncommitted at the time of
writing. `input_icons.rs`'s packs are now `Option<IconAtlas>` (a missing atlas is `None` with
the existing warning) and every lookup is `Option`-returning
(`InputIconAtlases::image_node(name)`); the `expect`s are gone. The pause menu's controls tips
(`modal_menu.rs`, `controls_tips.html`) emit icon placeholders only for icons a loaded atlas
has, so without atlases every row renders label-only.

Verification (playtest 0022): a `--no-render` client (implies `--no-common-assets`; both icon
atlases logged as omitted) connected, played, opened the pause menu with gamepad Start, and
`game/ui` listed all 11 tip labels (`Move` … `Stats`) and the Main Menu / Resume buttons with no
panic; Enter then resumed the game.
