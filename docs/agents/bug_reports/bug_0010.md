| Field | Value |

## Summary

Spawning a cube under the player and then a second one launches the player onto the spinning
cube. Afterwards, pressing W walks at an angle to the camera, permanently, and the angle grows
with the time spent on the cube. Prediction on and off are both affected.

## Steps to reproduce

The client is `--no-render`, inside `unshare -rn` (see playtest 0044 for the harness):

1. `game/trigger connect`, `game/select_level {"asset_path":"levels/minimal.level.ron"}`,
   `game/trigger play`.
2. Look straight down: `game/mouse {"input":"motion","dx":0,"dy":100}` × 6.
3. `game/trigger {"event":"spawn_cube"}`, wait 1.5 s, `game/trigger {"event":"spawn_cube"}`,
   wait 3 s.
4. Compare the client's look with `server/state.players[0].look`, then hold W for 1 s and
   compare the heading.

## Expected vs actual

- Expected: server yaw equals the camera's; W follows the camera.
- Actual: server yaw drifts to +0.035 while the client stays at 0, and W heads 0.035 rad off
  the camera. The drift grows with the time spent on the cube and with its spin rate; the
  owner's sessions showed far larger angles.

## Evidence

```
looking down     client look yaw -0.000 | server yaw +0.000
after cube 1     client look yaw -0.000 | server yaw +0.036   (player y 2.93, on the cube)
after cube 2     client look yaw -0.000 | server yaw +0.035
walk: heading +0.035; client yaw -0.000 (off +0.035), server yaw +0.035 (off +0.000)
```

The player body's `Rotation` stayed identity on both sides throughout, so the body never
turned.

## Root cause

Confirmed in `bevy_ahoy` 0.2 `src/kcc.rs`: `spin_character_look` (an `Update` system) rotates
`CharacterLook.yaw` by `platform_angular_velocity.y × dt` whenever the character is grounded on
a rotating body. The cubes spawn with random angular velocity
(`p19_server::spawn::apply_spawn_cube`), so standing on one is standing on a spinning
platform.

The server's look was an accumulator (`accumulate_look` added the client's per-tick deltas to
`CharacterLook`), so the spin became a permanent part of it. The client's camera never spins.
This is the same class as bug_0009: two accumulators of one delta stream, and one of them
changed.

## Fix

ADR 0017 removes the accumulators:

- The client sends its absolute camera direction as the `Look` action every tick.
- `apply_look` overwrites `CharacterLook` each tick before the KCC runs.
- The replicated `LookDirection` is written only from that input.

Verification, same steps after the fix, both prediction modes:

```
after cube 1   camera yaw +0.000 | server yaw +0.000 | Δyaw -0.0000   (y 2.91)
after cube 2   camera yaw +0.000 | server yaw +0.000 | Δyaw +0.0000
walk: heading -1.750; camera yaw -1.750 (off -0.0000), server yaw -1.750 (off -0.0000)
```

## Follow-ups

- A floor's spin no longer turns the player at all. If that ahoy feature is wanted, the
  client must apply it to its camera (ADR 0017, Open).
